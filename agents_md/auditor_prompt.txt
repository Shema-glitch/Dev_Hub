## AUDIT FRAMEWORK: The 7 Pillars of Premium UX
### 1. VISUAL HIERARCHY & BREATHING ROOM
- Does the eye naturally flow to the most important element first?
- Are cards, sections, and content blocks given adequate whitespace to *breathe*?
- Is information density balanced — not sparse, not cluttered?
- Do spacing ratios follow a consistent scale (4px → 8px → 16px → 24px → 32px → 
48px)?
- Are related elements grouped *closer together* than unrelated ones (Gestalt 
proximity)?
### 2. ALIGNMENT & OPTICAL PRECISION
- Are all text baselines aligned across columns and cards?
- Do icons sit perfectly centered within their containers?- Are card edges, input borders, and button edges on the same vertical/horizontal 
grid?
- Is there any pixel-level misalignment? (zoom in mentally to 1px precision)
- Do rounded corners maintain consistent radius across sibling elements?
### 3. STATE COMPLETENESS & FEEDBACK
Every interactive element must have these states:
- **Default** (resting)
- **Hover** (subtle lift, glow, or color shift — never jarring)
- **Focus** (keyboard accessible outline, never removed)
- **Active/Pressed** (satisfying micro-interaction)
- **Loading** (skeleton or subtle pulse — never a jarring spinner alone)
- **Empty** (helpful illustration or message, not a void)
- **Error** (actionable, human, never blaming)
- **Success** (brief, celebratory micro-feedback)
- **Disabled** (dimmed but readable, with tooltip explaining why)
### 4. TYPOGRAPHY & READABILITY
- Are font sizes following a clear type scale (12-14-16-18-20-24-32-40)?
- Is line height comfortable (1.4-1.6 for body, 1.2-1.3 for headings)?
- Are monospace fonts used *only* for code-related content?
- Is text contrast sufficient (WCAG AA minimum, AAA preferred)?
- Are there any orphan words or awkward text wraps?
### 5. COLOR & THEME INTEGRITY
- Dark mode is the *default and only* mode — every element respects it.
- No hardcoded white backgrounds or light-only shadows.
- Accent colors are used sparingly and *meaningfully* (actions, highlights, not 
decoration).- Semantic colors are consistent: red for errors, green for success, yellow for 
warnings.
- Gradients (if any) are subtle and purposeful, not gaudy.
### 6. MOTION & MICRO-INTERACTIONS
- Transitions are smooth (150-300ms), never abrupt.
- Hover states have subtle scaling or color shifts.
- Loading states animate (pulse, shimmer) rather than static text.
- Page/screen transitions feel connected, not jarring.
- Success actions have brief celebratory feedback (checkmark animation, subtle 
glow).
### 7. COHERENT NARRATIVE & FLOW
- The app tells a story: *Enter → Declare Intent → Work → Reflect → Leave → 
Return.*
- Screen transitions feel like chapters, not separate apps.
- Navigation reflects current state (active session indicator, unresolved badge).
- Empty states guide the user forward, never dead-end them.
- The interface *anticipates* what the developer needs next.

## AUDIT PROCESS
### Step 1: Screen-by-Screen Deep Dive
Inspect every screen thoroughly:
1. **Auth Screen** (Sign in / Sign up)
2. **Project Selection / Welcome** (No active session)
3. **Session Briefing** (Frozen state, heatmap, suggestions)4. **Active Session Dashboard** (Intent, timer, feed, commit sidebar)
5. **Weird Stuff Feed** (Log input, type badges, filters, real-time items)
6. **Activity - Commits Tab** (AI summaries, linked thoughts, file changes)
7. **Activity - File Changes Tab** (Heatmap timeline, file list)
8. **Feature Brainstormer** (Pitch input, wire map, validation, promote)
9. **Settings** (If present)
10. **End of Session Modal** (Audit results, unresolved, actions)
11. **Navigation / Sidebar** (Project switcher, links, unresolved badge)
### Step 2: Cross-Screen Consistency Check
- Navigation bar: same position, same styling on every screen.
- Project selector: consistent behaviour and appearance.
- Typography: headings, body, captions identical across screens.
- Spacing: same padding/margins on equivalent containers.
- Color tokens: identical hex values for identical purposes.
### Step 3: Interaction Flow Audit
- What happens when a user clicks "Start Session" with empty intent?
- What if the feed has 50+ logs — does it scroll smoothly?
- What if there are zero commits, zero ideas, zero unresolved?
- What does the timer look like at 30s vs 5s remaining?
- Can the user navigate away mid-session and come back?
### Step 4: Edge Case & Stress Testing
- Very long intent text (200+ characters)
- Very long log content (500+ characters)
- Rapid clicking (double-submission prevention)
- Network disconnection (offline state handling)
- Extremely narrow viewport (320px mobile)---
