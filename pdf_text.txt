1. PROJECT OVERVIEW
Dev Hub is a developer context engine that captures raw thoughts, links them to 
code changes, and helps developers seamlessly resume work on projects. The user 
interface has already been designed (see screenshots and prototype). The backend 
is entirely new and must:
All specifications must be fully implementable by a backend developer without 
requiring additional UI clarifications.
2. SYSTEM ARCHITECTURE
Real‐Time: WebSocket connections managed by a connection manager 
(broadcast per session).
Background Jobs: Celery / APScheduler for heavy AI processing 
(embedding generation, commit‐log linking, session freezing).
External Services:
Supabase Auth — user management, social OAuth, JWT issuing.
Gemini Pro API — embeddings, code‐diff analysis, summarisation, 
suggestions.
GitHub API — OAuth token exchange, repository events, issue 
fetching, diffs.
Frontend Communication: REST over HTTPS + WebSocket (wss://).

Configure Supabase project with Google, GitHub, and Email providers.
No custom user passwords stored; rely on Supabase’s auth.users.
On successful sign‐in, Supabase returns a JWT to the frontend.
Every protected endpoint must validate the JWT using Supabase’s public 
key (via supabase-py helper or manual JWKS check). Extract sub (user ID) 
to identify the developer.
When a user first accesses the backend, check if a developers row 
with supabase_user_id = sub exists; if not, create one and store any 
GitHub‐specific metadata (e.g., github_id, email).
All subsequent requests use the developer.id (UUID) for ownership 
checks.
All endpoints (except webhooks) require a valid JWT.
Ownership: Before modifying a resource (project, session, log), 
verify developer_id matches the authenticated user.
